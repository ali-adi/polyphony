# Polyphony Hygiene Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear the defects catalogued during the review and the two prior plans but never fixed — latent `NameError`s in live code, exception handling that converts programming bugs into ordinary failures, superseded modules and docs, and a README that describes a system that does not exist.

**Architecture:** No new subsystems. Four independent clean-ups, each with a test or a tool that prevents the defect class from returning. The linter is the important one: a manual review found one undefined name, and ruff found six.

**Tech Stack:** Python 3.11+, pytest 9.1.1 (venv), ruff (new dev dependency).

**Spec:** `docs/superpowers/specs/2026-09-21-polyphony-redesign-design.md`

## Global Constraints

- Python `>=3.11`. Runtime dependencies stay `click`, `pydantic`, `pyyaml`. **`ruff` is added to the `dev` extra only** — it must never become a runtime dependency.
- **Never write AI attribution into a commit.** A repo hook blocks these and the commit will fail.
- **Never run** `git push`, `git merge`, `git reset --hard`, or `git clean`. Work on the current branch (`redesign-spec`) only.
- Baseline is **265 passed, 3 deselected**; verify with `.venv/bin/python -m pytest -q`.
- Commit with an explicit pathspec (`git commit -m "..." -- <files>`), never the bare index.
- Nothing in this plan touches a repository other than `ai-orch` itself.

## Task 2: Stop adapters converting programming errors into failed results

**Files:**
- Modify: `executors/claude_executor.py`, `executors/agy_executor.py`, `executors/cursor_executor.py` (the outer `except Exception` in each `execute()`)
- Test: `tests/test_executor_errors.py` (create)

**Interfaces:**
- Consumes: the three adapters.
- Produces: no new API. Behavior change — `execute()` returns a failed `ExecutorResult` for *environment* failures, and propagates *programming* errors.

**Context.** Each adapter's `execute()` currently ends with:

```python
        except Exception as e:
            return ExecutorResult(success=False, error=str(e), exit_code=1, ...)
```

That catches `NameError`, `TypeError`, `AttributeError` — bugs in Polyphony
itself — and reports them as though the CLI failed. In Plan 1 Task 3 this is
precisely what masked a `NameError`: the adapter returned
`success=False, error="name 'session_id' is not defined"`, which reads like an
ordinary executor failure.

The orchestrator's design principle (spec §3) is that an unrecognized failure
must surface and stop rather than be absorbed. A crash is strictly better than
a wrong result here: the operator is watching 70% of the time, and a silent
"executor failed" sends the lead reasoner chasing a phantom.

Expected exceptions are narrow and known: `subprocess.TimeoutExpired` (already
handled separately), `OSError` / `FileNotFoundError` (binary vanished,
permission denied), and `subprocess.SubprocessError`.

- [ ] **Step 1: Write the failing tests**

Create `tests/test_executor_errors.py`:

```python
"""Adapters must not disguise Polyphony's own bugs as executor failures."""

import subprocess

import pytest

from executors.agy_executor import AgyExecutor
from executors.claude_executor import ClaudeExecutor
from executors.cursor_executor import CursorExecutor

ADAPTERS = [
    (ClaudeExecutor, "claude"),
    (AgyExecutor, "agy"),
    (CursorExecutor, "cursor"),
]


@pytest.mark.parametrize("cls,name", ADAPTERS, ids=[n for _, n in ADAPTERS])
def test_programming_errors_propagate(cls, name, tmp_path, monkeypatch):
    """A NameError in our own code must not become 'the CLI failed'."""
    def boom(*a, **k):
        raise NameError("name 'session_id' is not defined")

    monkeypatch.setattr(subprocess, "run", boom)
    ex = cls(binary_path="/bin/echo")

    with pytest.raises(NameError):
        ex.execute(instruction="hi", cwd=str(tmp_path))


@pytest.mark.parametrize("cls,name", ADAPTERS, ids=[n for _, n in ADAPTERS])
def test_environment_errors_become_failed_results(cls, name, tmp_path, monkeypatch):
    """A missing binary is a real executor failure, not a crash."""
    def missing(*a, **k):
        raise FileNotFoundError("No such file or directory: 'binary'")

    monkeypatch.setattr(subprocess, "run", missing)
    ex = cls(binary_path="/bin/echo")

    res = ex.execute(instruction="hi", cwd=str(tmp_path))
    assert res.success is False
    assert "No such file" in (res.error or "")
```

- [ ] **Step 2: Run tests to verify they fail**

Run: `.venv/bin/python -m pytest tests/test_executor_errors.py -q`
Expected: the three `test_programming_errors_propagate` cases FAIL — `DID NOT
RAISE <class 'NameError'>` — because the broad handler swallows it. The three
`test_environment_errors_become_failed_results` cases should already pass.

- [ ] **Step 3: Narrow the handler in each adapter**

In **each** of `executors/claude_executor.py`, `executors/agy_executor.py`, and
`executors/cursor_executor.py`, find the outer handler in `execute()`:

```python
        except Exception as e:
```

and change it to:

```python
        except (OSError, subprocess.SubprocessError) as e:
```

Leave the handler body exactly as it is, and leave the separate
`subprocess.TimeoutExpired` handler above it untouched. `OSError` covers
`FileNotFoundError` and `PermissionError`; `subprocess.SubprocessError` covers
the subprocess family. Everything else — the bug family — now propagates.

**`CursorExecutor` needs a second, identical change.** Unlike the other two
adapters, its `execute()` calls `self.is_available()` first, and
`is_available()` runs its own `subprocess.run` health probe wrapped in its own
broad handler at `executors/cursor_executor.py:89`:

```python
        except Exception:
            CursorExecutor._class_is_agent_ready = False
```

Change that one to:

```python
        except (OSError, subprocess.SubprocessError):
            CursorExecutor._class_is_agent_ready = False
```

This is the same defect, not a separate concern: a missing binary raises
`OSError` and correctly yields `False`, while a `NameError` should propagate
rather than being recorded as "cursor is unavailable" — and, because the result
is cached at class level for 300 seconds, that wrong answer would then persist
across every subsequent call.

Change only these two handlers in `cursor_executor.py` and one in each of the
other two files. Leave every other `except Exception` alone.

Each file already imports `subprocess` at module level, so no import changes
are needed.

- [ ] **Step 4: Run tests to verify they pass**

Run: `.venv/bin/python -m pytest tests/test_executor_errors.py -q`
Expected: `6 passed`

- [ ] **Step 5: Verify nothing regressed**

Run: `.venv/bin/python -m pytest -q`
Expected: `275 passed, 3 deselected`

If a pre-existing test now fails because it relied on a bug being swallowed,
STOP and report which one rather than re-broadening the handler.

- [ ] **Step 6: Confirm the real adapters still work**

Run: `.venv/bin/python -m pytest tests/smoke -m smoke -v`
Expected: `3 passed` — narrowing the handler must not break genuine execution.

- [ ] **Step 7: Commit**

```bash
git commit -m "fix: let programming errors propagate out of adapters

execute() caught bare Exception and returned success=False with the
message, so a NameError in Polyphony's own code read as an executor
```

## Deliberately deferred

- **149 `F401` unused imports and 16 `F841` unused locals.** Most are in the 24
  orphan modules a later plan deletes. Enable those rules after the deletion
  pass, not before.
- **`explain.py:110` assigns `events` and never reads it.** A real bug, but
  `explain.py` is slated for deletion; fixing it would be work on a corpse.
- **`CursorExecutor`'s class-level availability cache.** `_class_is_agent_ready`
  is shared across every instance with a 300s TTL, so one transient probe
  failure marks cursor unavailable process-wide for five minutes. Narrowing its
  handler (Task 2) removes the worst case — caching a swallowed bug — but the
  shared-mutable-state design remains and belongs with the loop rewrite.
- **CI.** Running ruff and pytest on push needs a decision about where CI runs
  for a local-first personal tool. The linter is available locally now, which
  is what matters for a single-operator workflow.
